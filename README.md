AI 大模型核心能力——从提示、RAG 到 Agent 的技术脉络
Python 底子打好后，下一步是理解 AI 大模型的核心能力。开发 AI 产品，不是会调一个模型接口就行，而是要理解模型如何工作、能力边界在哪、如何用工程手段弥补不确定性。课程应围绕六条技术脉络展开：模型基础、提示工程、上下文管理、RAG、工具调用与 Agent、微调与推理优化。

第一，模型基础。你需要理解 token、嵌入、注意力机制、上下文窗口、温度、 Top-p、频率惩罚等概念。不必推导公式，但要知道它们如何影响输出。token 决定计费和上下文长度；嵌入决定语义检索能力；注意力决定长文本关联；温度影响创造性与稳定性；上下文窗口限制记忆容量。还要理解大模型是概率生成系统，不是数据库，也不是逻辑引擎。它会编造、会漂移、会受提示顺序影响。只有接受这一点，才会设计校验、引用和拒答机制。

第二，提示工程。提示不是聊天，而是规格说明。一个可用的提示通常包含角色、目标、输入、约束、步骤、输出格式和示例。课程要训练结构化提示：把模糊需求转成可执行指令，把业务规则写进系统提示，把动态数据放进用户提示，把输出格式固定为 JSON 或表格。还要掌握少样本示例、思维链、分步推理、自我检查和输出校验。提示工程的目标不是“让模型更聪明”，而是“让结果更稳定、更可验收”。

第三，上下文管理。模型本身没有记忆，记忆来自你喂给它的上下文。上下文包括系统指令、历史对话、检索证据、工具结果和当前任务。上下文窗口有限时，要动态裁剪、摘要压缩、按相关性召回。多轮对话要保存状态、摘要历史、处理指代和省略。上下文冲突时，要提示矛盾而非强行回答。敏感信息要脱敏，权限要过滤。上下文工程是 AI 产品效果的关键变量，也是 Python 工程师最能发挥工程能力的地方。

第四，RAG 检索增强生成。RAG 解决的是模型知识过时、私有数据无法访问和幻觉问题。技术流程包括采集、清洗、切分、嵌入、索引、检索、重排、生成和引用。数据源可以是文档、网页、数据库、工单和聊天记录。切分策略影响召回，嵌入模型决定语义匹配，重排模型决定证据质量。生成阶段要强制引用来源，检索为空时明确拒答。RAG 的难点不在搭建，而在数据更新、权限隔离、检索评测和持续优化。课程应让学员理解，RAG 是数据工程、检索工程和生成工程的组合。

第五，工具调用与 Agent。大模型不能直接查数据库、发邮件、建工单，必须通过工具。工具调用要定义名称、用途、参数、权限、超时和返回格式。工具分只读、写入和高危三类，权限逐级收紧。Agent 是目标驱动的循环：规划、执行、观察、修正、停止。它需要记忆、工具、状态和审查。课程要讲清楚停止条件、步数限制、预算控制、失败重试和人工中断。多 Agent 不是越多越好，只有在任务需要并行、隔离或专业分工时才引入。
